AIAA 4051 自然语言处理课程项目

我们想知道：**智能体在 ALFWorld 做错一次之后，能不能利用文字反思，在下一次尝试里改变行动、少犯同样的错？**

## 基线代码和实验结果怎么放

- **基线代码进仓库。** `scripts/run_baseline.py` 是 A/B 组的运行入口，复用 `src/` 的 Agent、环境和评估逻辑。把对应的依赖、模型与实验配置、B 组提示词、固定任务编号一并版本化。复用的 ALFWorld 和 Reflexion 上游代码记录来源和固定版本，并在复现说明里写清获取方式。
- **可公开的结果进 `results/`。** 保存基线与正式评测的汇总表、图表和失败案例。表格注明开发集或留出集、A/B/C 条件、运行编号和对应 Git 提交。每次运行关联配置、模型与提示词版本、任务 ID、随机种子、指标与 GPU 耗时。
- **完整轨迹按运行编号归档。** 日志包含每步观察、动作、环境反馈、反思及运行成本，也保留失败运行。小型且可公开的轨迹可以随案例提交，大量或受限日志放团队共享的实验产物位置。通过 `logs/README.md` 说明日志格式和查找方式，在 Notion「实验与结果」中维护内部链接。模型权重、大型原始数据和凭据由本地或团队存储管理。

## 实验设计

在文本交互环境 ALFWorld 中复用 Reflexion 实现，固定一个开源指令微调模型，只做推理实验。

| 条件 | 第一次失败后怎么重试 |
| --- | --- |
| A · 无反思 | 从相同初始状态重试，重试时无反思记忆 |
| B · 原始反思 | 使用原始 Reflexion 反思提示词和记忆机制 |
| C · 自定义反思 | 替换反思提示词，其余设置与 B 保持一致 |

- **开发与评测**：用固定 10 个开发任务调试。在 30 个留出任务上正式评测，评测前冻结 C。每个任务最多尝试 3 次，每次最多 30 个环境动作。每次重试恢复相同初始环境，成功即停。
- **评估**：统计首次成功率、三次内累计成功率、首次失败后的恢复率，以及模型调用数、输入输出词元和 GPU 耗时。恢复率按各组实际分子和分母报告。
- **证据**：样本充足时分析 5–10 组失败到重试的真实轨迹，区分反思错误、反思正确但行动未纠正、行动得到纠正。团队预算上限为 30 GPU 小时。

## 怎样让队友看得见你的进展

- **开始任务**：在 Notion 确认负责人和验收标准。工程任务在同一条 Notion 记录挂 GitHub Issue 或 PR。项目状态统一在 Notion 更新。
- **提交代码**：一个功能分支对应一件事，`main` 保持可运行。PR 写清做了什么、如何验证、结果或日志在哪，由另一人复核。
- **交接关键进展**：阶段变化、重要决策、实验完成或出现阻塞时，先更新 Notion 或 GitHub 的原始记录，再在 `AI_SYNC.md` 记一条交接。用一句话写明「谁做了什么 → 证据在哪 → 谁接手、什么时候完成」。先拉取最新 `main`，通过 PR 保留双方的更新。
- **记录实验**：每次运行有唯一编号，关联 Git 提交、模型/提示词版本、任务 ID、种子和解码配置，并附指标、GPU 耗时与轨迹位置。失败运行也保留记录。
- **积累评分证据**：可运行命令和 PR 对应代码，带轨迹的结果表和案例对应报告分析，流程图和图表对应海报。Notion「评分标准与交付物」关联这些证据。

**填写示例（仅示范）**：实验负责人完成 A 组开发集试跑 → PR `#编号`、运行 `run_id` → 研究负责人在约定日期前复核失败轨迹。
