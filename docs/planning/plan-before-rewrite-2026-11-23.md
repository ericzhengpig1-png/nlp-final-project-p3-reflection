# P3 研究计划

**交付目标**　在同一个 ALFWorld 智能体上，用 A 无反思、B 原始反思、C 自定义反思回答一个问题：只改失败后的反思提示词，能否让智能体在重试中完成更多任务，代价是多少？最终框架只采用符合 C 组约束、经过对照验证的提示词。负责人批准本轮研究方向和预算。AI 在该方向和预算内自行检索、试提示词变体、跑开发集和写报告。换方向、追加预算和冻结 C 时，由负责人决定。

## 一轮研究怎么跑

1. **找方向。** 每轮对照上一份报告中的具体失败查资料。优先原论文、作者代码和已有日志。记录出处、版本或日期、相关段落、能迁移成哪一句提示词。对新想法只给最多三个候选，每个写明观察、假设、最小对照和预估成本。论文结果标为外部证据，本项目的收益等实跑后再填。
2. **定小试。** 为选中的方向分配 C 编号。运行前在步骤报告中登记唯一改动、B 或上一版 C 的准确版本、固定开发题、种子、主要指标、预期失败信号、预算上限。固定模型与量化、动作提示和示例、解码、原有记忆机制和输入、重置方式、每题最多 3 次尝试、每次 30 个环境动作。C 只替换英文反思提示词。需要额外检索、工具、模型调用或程序化改写记忆的方案记入历史想法。
3. **从两题到十题。** 固定两题先验收提示词确实注入、重试记忆正确、A/B/C 的首轮输入与种子一致、原始日志齐全。再跑登记的全部 10 个开发任务，与同条件的 B 逐题配对。两题只用于验通流程。改提示词即换版本和 run ID。
4. **决定去留。** 主指标为三次内累计成功数，配套报告首败后恢复分子/分母、仅 C 成功和仅 B 成功的任务、推理成本。建议以十题净多成功至少 1 题作为**进入复核**的门槛。用事先登记的另一组配对种子复测 B 和候选 C，复查至少一条“反思 → 下次动作 → 环境反馈”的轨迹。两个登记种子均比相同种子的 B 净多成功至少 1 题、轨迹能解释改善且成本在预算内，可推荐冻结。此门槛用于筛选，不代表统计显著。打平但明显省成本可单列为效率发现；结论写实际差值，十题打平或波动写“未见稳定收益”。复测预算不足时记录“待复核”。
5. **组合与冻结。** 两个提示词变体各自有收益时，在相同开发任务和种子下对比 B、C01、C02、C01+C02，检验组合相对最佳单项是否还有收益。优先保留表现相当时更短、成本更低的版本。负责人选定后冻结提示词全文和哈希、运行代码、配置、任务清单与种子，一次性评测登记的 30 道留出题。正式评测后如实记录持平、退步或改进。所有候选都无稳定提升时，仍可冻结一个合规 C 来回答课程问题，将其标为待检验方案。

## 研究分工与 Git 分支

| 角色 | 并行工作 | 交付 |
| --- | --- | --- |
| 协调对话 | 维护方向队列、预算、GPU 排队顺序与恢复点 | 更新本表，向负责人提交下一项决定 |
| 文献与轨迹分析 | 一边查原始文献，一边从开发轨迹抽取支持例、反例 | 有出处的假设、轨迹定位和可执行的提示词改动 |
| 实验与独立复核 | 实验者按登记配置运行，复核者从日志重新算表并检查比较条件 | 实验报告及复核意见，资源允许时与下一轮资料收集并行 |

每个获选方向从**同一可复现基准提交**开独立本地 Git 分支和 worktree（独立工作目录），例如 `research/c01-observation`、`research/c02-next-action`。把共同支持 C 的最小改动放在 `feat/course-c-runner`，先在这个分支回归 A/B，再作为两个方向的共同起点。记录起点 SHA、worktree 位置、提示词版本；集成分支 `integration/course-final` 只接收冻结的课程实现。当前工作区在历史 Anchor 分支，且有未提交文档。新 worktree 从核实后的课程基线创建，历史 A/B 分支可从 `feat/alfworld-baseline` 查起；新 worktree 需单独核对被 Git 忽略的数据、模型与日志路径。

每个方向独占自己的报告、运行目录和编号。协调者给并行任务分配方向编号、数据和卡时，每个实验分支从协调工作区读取本计划，回交报告和产物位置。单卡上的模型运行依次排队，避免成本比较受并发干扰。多卡并行时登记设备、作业号和各卡分配时长。分支可独立推进，协调者负责将报告和证据汇总到同一个本地交接位置，先归档报告再关闭工作线。在入口报告登记基准 SHA 和实际改动。有未提交代码时，保存可重放的补丁及新文件和哈希，供独立工作区复核。本轮约定只在本地协作，Git 提交、推送、正式合并沿用负责人给出的权限。

## 报告与成本

每完成一个能回答问题的步骤就交一份短报告，如文献筛选、环境验收、两题试跑、十题比较、复核或冻结。保存到 `docs/reports/<方向>-<序号>-<步骤>.md`。进行中的研究每个北京时间自然日至少汇总一次进展；间断后首次接手先补记完成量和断点。协调者在有实质进展的当天合并各线程结果，列出推荐、待选项、已用/剩余预算。遇到预算不足、协议偏离或运行故障，当步写明影响和可继续的工作。

每份报告控制在一屏，详细图表、原始轨迹与失败运行用链接保留。按下面五行写：

| 字段 | 必填内容 |
| --- | --- |
| 判断 | 一句话结论，说明推荐继续、复核、停止或待决定 |
| 怎么比 | 具体假设、唯一变化、任务划分与数量、种子、对照版本 |
| 证据 | 实验用一张逐题表或配对图，给出分子/分母和成本，附至少一个决定性的轨迹定位。查资料用原文和适用性表，环境问题用命令与实际输出 |
| 能解释到哪里 | 哪些题改善、哪些退步、替代解释，写明不确定性 |
| 复现与下一步 | 分支和提交或补丁、配置及提示词哈希、run ID、日志位置、资源消耗、下一动作和负责人 |

项目总上限为 **30 GPU 小时**。每轮登记总额、已用、已预留与本轮可用卡时，先给冻结后的 30 题 A/B/C 留出预算。计费卡时用分配时长乘卡数，后端推理秒另列。当前历史账目和学校 GPU 配额尚未核实。每个作业开跑前核对余额和预估，达到本轮上限即停止新增 GPU 作业，转做日志分析并交报告。

- 当前基准程序支持 A/B 的 manual、pilot、dev。C 与留出入口尚待实现。先在隔离工作区实现最小提示词切换，核对 A/B 行为、B/C 首轮一致、重置一致和 C 仅在失败重试时收到反思。验收通过再测新提示词。[基线说明](../experiments/baseline.md)
- 迁移的 WSL 环境含旧路径。首次实验前核对实际解释器、依赖、数据位置和四动作教程。遇到环境问题先写检查结果，修复或重建按负责人授权处理。资料检索与现有轨迹分析可独立进行。[迁移记录](../handoffs/migration_2026-11-22.md)
- 每次接手先读取本表、各方向最近报告和对应运行清单。有完整结果则复核，有运行中的作业则接着跟踪，失败或中断则保留证据、登记原因，用新编号重试。每次交接留下运行状态、累计预算、证据位置、下一动作以及需要负责人判断的事项。遇到某个方向阻塞，继续执行其他已批准且有预算的工作。
- 课程节点按现有项目记录为 12 月 7 日海报、12 月 14 日最终交付，提交要求以课程最新通知为准。旧计划、原始实验设计和证据索引可从[11 月 22 日复审](review-2026-11-22.md)查阅。
