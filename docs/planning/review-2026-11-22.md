## 2. 项目如何工作，前人的工作分别是什么

### 2.1 一次任务怎么执行

以“把洗干净的刀放到台面”为例：模型先找刀并拿起，再去水槽清洗，最后放到目标台面。环境逐步返回观察，并通过 `state.won` 判定任务完成。模型说“完成了”不算成功。

每题最多尝试 3 次，每次最多执行 30 个环境动作。失败后恢复同一个初始环境，下一次重新开始；成功后立即停止。10 个开发任务用于调试，30 个留出任务用于最终评测。

| 组别 | 失败后带进下一次尝试的内容 | 要回答的问题 |
| --- | --- | --- |
| A：无反思 | 不保留反思记忆 | 单纯增加尝试机会能做到什么程度？ |
| B：原始 Reflexion | 用原始反思提示词生成的文字 | 增加反思是否优于单纯重试？ |
| C：自定义反思 | 用团队改写的反思提示词生成的文字 | 改善反思内容是否能改善后续行为？ |

B/C 的模型、动作提示词、示例、解码设置、记忆机制和任务预算保持一致，C 只改反思提示词。A 的后续尝试采用预先规定的不同采样种子，因此无反思也可能在重试中成功。

## 5. 已经看出的端倪：事实、解释与下一步验证

### 5.1 B 的反思质量值得优先处理

**事实一：10/10 条反思都生成到 256 token 上限，`stop_type=limit`。** 这是输出到限，不等同于上下文溢出。部分文本重复枚举地点，并在半句话结束。

**事实二：CD 任务出现可直接核对的事实错误。** B 第一次尝试第 11 个环境动作是 `take cd 3 from drawer 5`，环境明确返回 `You pick up the cd 3 from the drawer 5.`；该次反思开头却写“未能找到 CD”。下一次需要解决的重点已经是拿到 CD 后如何完成灯下检查，而这段反思仍把注意力放回找物品。[E2]

这支持一个值得检验的假设：短而基于观察的反思，可能比重复、错误的失败总结更有帮助。它尚未证明 C 会提高成功率，也不能推出“只要加大模型或增加 token 就会改善”。建议保持现有预算，先用 C 提示词约束输出简洁性和事实依据。

放书案例还提醒我们：B 重试成功，不代表它的反思正确。反思曾无依据地建议从抽屉拿书，实际成功路径是在新尝试中走到餐桌并发现书。案例标注必须把“反思正确”“采取了相关改变”“最终成功”分别记录。

### 5.2 Anchor 存在动作选择层面的共同失败

运行提交 `0547e3ff98fb34e03f9cdb7c68f631111ae5014d`。6 个训练任务产生 30 条候选笔记，其中 12 条正例、18 条纠错，筛选后留下 9 条，全部是纠错笔记。模型训练轨迹全部失败，正例另由官方训练示范补充。这是移植时的重要条件。[E4–E5]

| 指标 | 筛选版 | 不筛选版 |
| --- | ---: | ---: |
| 十题三次内成功 | 0/10 | 0/10 |
| 环境动作数 | 900 | 900 |
| 实际执行 `take` | 0 | 0 |
| 合法候选中存在至少一个 `take` 的决策数 | 270 | 283 |
| 注入笔记的决策数 | 523/900 | 900/900 |
| 后端推理时间 | 274.26 秒 | 276.47 秒 |
| 端到端时间 | 415.58 秒 | 417.47 秒 |

`take` 候选计数包括任意可拿物品，并不保证是任务目标。但它足以说明：不能把零拿取简单归因为“环境从来没提供拿取命令”。两组共同存在从观察走向有效操作的障碍。建库另用 107.14 秒，筛选另用 13.94 秒。

**当前最缺的对照是：完全相同的 Anchor 动作策略，笔记库为空。** 没有这组，就无法区分动作提示/解码本身的问题和笔记干扰。历史 A/B 使用自由续写、不同示例数量和历史组织方式；Anchor 使用合法命令列表、语法约束、一个示例及截取后的历史。历史 6/10 与 Anchor 0/10 只能用于提醒“整套移植退化”，不能单独归因于筛选。

### 5.3 检索门槛没有挡住低相关笔记

本地 `src/agent/anchor.py` 的 `retrieve()` 先要求任务类型相同、建议动作类别当前可行，再计算：

`score = 0.50 + 0.20 + 0.30 × 词汇重合度`

配置门槛为 `retrieval_threshold = 0.45`。因此通过前两个条件的笔记，即使词汇重合度为零，得分仍为 0.70，已经超过门槛。当前门槛无法排除这类笔记，词汇重合主要用于排序。[E6]

这与“放书召回肥皂瓶笔记”的记录相符。笔记还携带旧任务具体物品和柜子编号，迁移到新房间可能误导行为。**这是已确认的实现性质；它对零成功率造成了多大影响，仍需对照实验。** 不应只改一个阈值、看到分数变化就声称根因解决。

### 5.4 局部动作偏好改善不等于任务完成

笔记 `anchor-attempt-1-02-1-01` 让原训练决策中 `open` 类概率约从 49.53% 降到 2.59%，说明笔记改变了这个决策点的分数。当前探针按首 token 合并候选，因此测量粒度主要是动作类别，无法充分区分“去柜子 2”与“去柜子 3”这类共享前缀的命令。

筛选通过还需要面对新场景是否适用、模型是否选中正确物品、后续多步是否完成等问题。9 条笔记全部来自纠错，正例全被过滤，也提示应检查源动作、示范分布与当前策略是否匹配。这里都是下一轮的诊断方向，不是已证明的原因。

## 8. Anchor 支线如何继续，什么时候停止

建议先投入半天完成最小诊断，不抢占 C 和留出评测的关键时间。依次进行，上一层没解释清楚就不要同时改多个因素。

| 顺序 | 实验或检查 | 解决的问题 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1 | 相同 Anchor 策略、空笔记库，先跑两题，再视情况跑十题 | 零拿取是否在无笔记时也存在？ | 得到完整可对照轨迹。 |
| 2 | 固定有目标物品可拿的开发决策点，检查 prompt、候选顺序、语法约束与实际输出 | 动作提示或解码是否压制拿取？ | 找到可重复的现象；不能靠查看候选列表就认定解码无误。 |
| 3 | 仅调整检索门槛/相关性判据，保留其余设置 | 无语义重合、旧物品编号笔记是否导致干扰？ | 输出每次召回的理由和前后行为差异。 |
| 4 | 在可正常行动的统一策略下比较空库、全部候选、筛选库 | 筛选是否带来端到端收益？ | 三组只在记忆策略上有预定差异，候选来源一致、库只读。 |
| 5 | 有需要再加等数量随机笔记对照 | 收益来自筛选内容，还是笔记数量更少？ | 作为机制补充，避免把长度和数量效应误称为筛选质量。 |

在上述诊断前，应补读 Anchor 原论文并整理“原文设置—本地实现—偏差影响”表，特别核对首 token 探针、方向规则、检索、在线建库和示范补充。

若半天诊断仍不能恢复基本拿取与任务推进，保留失败证据并将支线降级为附录或局限分析。该时间上限是推进建议，目的在于确保课程主线按时交付。
