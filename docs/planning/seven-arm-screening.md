执行平台已明确为学校 GPU，本地不运行模型。上传、环境准备、Slurm/容器操作与运行条件见[学校 GPU 流程](../experiments/school-gpu-runbook.md)。学校实际入口、课程分区与额度仍待核实。

## 目的与比较关系

下一步建议把五个完整提示词作为五个独立 C 候选，与 A、B 在同一轮比较。回答两个问题：**相对原版反思 B，哪个提示词改善任务结果；相对无反思 A，这些收益是否值得反思成本。**先完成开发筛选，再决定最终课程 C。

| 组别 | 行为 | 比较用途 |
| --- | --- | --- |
| A | 失败后直接重试，无反思记忆 | 无反思参照 |
| B | 原版 Reflexion 反思指令 | 五个新提示词的主要对照 |
| S1 | 观察证据约束 v1 | 检查事实错误方向 |
| S2 | 失败步骤与前置条件 v1 | 检查失败归因方向 |
| S3 | 根据新证据修订旧建议 v1 | 检查跨轮更新方向 |
| S4 | 剩余目标与完整重试路径 v1 | 检查目标遗漏方向 |
| S5 | 去重与信息密度 v1 | 检查表达效率方向 |

文本来自[完整草案与原版对照](../reports/S1-S5-prompt-drafts.md)及[独立提示词目录](../../prompts/reflection_candidates/)。本轮每个方向只用已有一版，不加入旧 C01 v1、旧 C02、组合提示词或 Anchor，避免候选数量在取分过程中变化。

## 工作量与执行顺序

采用[固定任务清单](../../configs/task_registry.json)的全部 **10 道 development 题**，覆盖六种任务类型。盘子、锅铲均在其中；不只选择这两题或历史首败六题。开发题已经用于设计提示词，因此这里是开发集筛选，不能把结果当作独立泛化验证。

1. **运行前准备（代码与无模型检查已完成）。**接入五份指令并复用原 A/B 循环，核对六个反思组、A 无反思、原 B 不变及示例/记忆机制。新的条件选择明确支持 S1–S5，不再只接受 B。学校部署后仍须在当地环境执行预检。
2. **第一轮。**七组各跑完整十题，基础种子 4051，共 **70 个任务—组别—种子单元**。中途只检查运行正确性和预算，不因少数题分数高低改提示词、删题或淘汰某组。
3. **第二轮。**七组各跑同样十题，基础种子 4052，再做 **70 个单元**。第一轮、第二轮使用相同冻结文本和程序；不只给第一轮冠军追加种子。
4. **配对汇总。**完成全部两轮后展示七组结果、逐题胜负、成本及错误案例。根据预定规则给出保留或不保留建议，再由用户决定最终 C 或进一步研究。

总计 **7 组 × 10 题 × 2 个种子 = 140 个单元**；每个单元最多三次尝试，所以最多 420 次环境尝试。首次或第二次成功就停止，不强制跑满三次。相同十题换种子仍只有十个不同任务，不变成二十个独立任务。

建议分轮报告，但两轮都完成后再作主要排序。若预算只能覆盖一轮，就明确交付“单种子探索结果”，不把它称为稳定提升。基础运行参数或程序需要修复时记录新版本；已受影响的组不能与修复后组直接混算。

## 控制变量

| 项目 | 七组共同约束 |
| --- | --- |
| 模型与推理后端 | [baseline.json](../../configs/baseline.json) 的 Qwen2.5-1.5B-Instruct Q4_K_M、固定模型 revision/哈希、llama.cpp b12244；raw completion |
| 环境 | ALFWorld 0.4.2、TextWorld 1.6.2；相同任务文件与初始状态哈希；各次重试恢复任务初始状态 |
| actor 与示例 | 同一动作指令、同一组原 actor 示例；六个反思组保持两份原反思示例 |
| 反思输入与记忆 | 相同构造和注入规则，各组使用自己的真实失败轨迹与反思；组间、任务间不共享生成的记忆 |
| 尝试与动作 | 每题最多 3 次尝试；每次最多 30 环境动作、49 策略回合；成功即停；末次失败不再生成反思 |
| 上下文与输出 | 上下文 8192 token；动作输出 128、反思输出 256；不改变停止规则，不裁掉不利轨迹 |
| 解码 | temperature 0.2、top_p 1.0、top_k 0、min_p 0.0、repeat_penalty 1.0；保留当前逐请求种子公式与 cache_prompt=False |
| 种子配对 | 基础种子分别 4051/4052；每个种子下七组使用同一任务清单与种子规则，不使用按组编号改变种子的做法 |
| 硬件与负载 | 同一设备和后端配置，单模型任务串行；保留一个服务 slot；记录硬件、实际分配时长、失败/空闲占卡时间 |

两个细节尤其需要验收：

- **第一次尝试尚未产生反思。**同一任务与种子下，七组应使用相同的首轮 actor 输入和空记忆，并核对首轮行为与结果。若出现差异，先查输入、种子或后端非确定性，不能把首轮差异解释为反思收益。
- **重试后轨迹允许分叉。**不同反思改变后续行动是研究目标。控制输入的构造规则，而不是把 B 的第二次失败轨迹强行替换进所有组。S1–S5 指令的长度不同，也是这些文本的实际成本，不能偷偷补齐或截断成相同长度。

每个种子按 registry 的任务顺序执行；在每个任务内循环七组，组序采用固定轮转：初始顺序 A、B、S1、S2、S3、S4、S5，第 i 道任务左移 i 位（i 从 0 开始），第二个种子再偏移一位。记录实际顺序，避免某组总占据冷启动位置；七组均独立重置环境与记忆。

## 指标、排序和结论边界

**主指标：每个种子下三次内成功数 / 10，以及各 S 相对同种子 B 的配对净变化。**同时报告相对 A 的结果。

对每个 S 统计“仅 S 成功”的任务数 W、“仅 B 成功”的任务数 L；净多成功 W−L。汇总两个种子时先展示各自结果，再计算平均差。不能只挑最高种子；同题多次尝试、两个种子不作为独立任务重复计数。

**辅助指标：**首次成功数；首败后恢复数/首败数；成功发生在第几次；环境动作、模型调用、输入/输出 token、推理时间和实际 GPU 卡时。五类错误按[既定口径](../experiments/reflection-error-taxonomy.md)分析，区分文字修正、actor 是否采用和最终成功。第二次反思的更新质量要单列适用分母，不把没有第二次反思的任务算成更新失败。

| 结果形态 | 预定解释 |
| --- | --- |
| 两个种子都比 B 净多成功至少一题 | 值得优先保留的开发候选；这只是筛选门槛，不表示统计显著或泛化已成立 |
| 一个种子提升、另一个持平或下降 | 波动或种子敏感的探索信号，不能只报提升那轮 |
| 相对 B 提升，但仍落后于 A | 反思提示词有局部改进，但尚未证明优于无反思重试 |
| 成功数不变、反思更准或更省 token | 报告质量/成本变化，不称任务成功率提升 |
| 提升题与退步题同时存在 | 逐题展示 W/L；不只用总分掩盖损失 |
| 五版均无稳定收益 | 如实报告，不靠反复改版本、换种子或换题制造冠军；下一设计另行决定 |

候选选择先看两个种子的任务成功与配对变化，再看退步题和波动；并列时参考实际成本与案例可解释性。十题上一题就是十个百分点，不能把一个小差异写成确定结论。本轮比较五个候选，更应完整披露全部候选，避免只展示最好的一个。

保留既有 30 道 held_out 作为最后 A/B/最终 C 的评测；在开发阶段选定并冻结 C 后再使用，不能先让七组在留出题上竞赛再选冠军。报告开发过程及搜索成本的做法也符合 [Dodge 等《Show Your Work》](https://aclanthology.org/D19-1224/)强调的完整实验报告原则；该论文不为本方案的具体题量或种子数提供保证。

## 预算估算与启动条件

依据[历史计时提取](../reports/C01-01-analysis.json)粗估，假设同等有效吞吐，五个 S 的单位成本接近 B；两种情景分别采用原运行的尝试数，或每题跑满上限并使用历史请求耗时 P95。它们是参考情景，不是承诺范围或严格上界。

| 工作量 | 沿用历史工作量的估计 | 跑满工作量、历史 P95 耗时情景 |
| --- | ---: | ---: |
| 七组 × 十题 × 一个种子 | 约 36 分钟 | 约 108 分钟 |
| 七组 × 十题 × 两个种子 | 约 72 分钟 | 约 217 分钟，即 3.6 小时 |

推导：历史每十题 A 约 278.51 秒，B 约 312.42 秒；一轮为 A + 6×B。满工作量情景 A 约 884.41 秒、B 约 936.82 秒，同样计算。单轮模型调用上限为 10×147 + 60×149 = 10,410；两轮 20,820，其中反思最多 240 次。实际成功提前停止会减少调用。

以上未覆盖部署、模型加载、准备与空闲占卡；新指令和新轨迹也会改变成本。**建议为完整两轮暂按最多 5 GPU 小时讨论预算**，在目标设备核实吞吐和实际余额后登记；该数值不是已批准额度。旧两题 B/C 的 0.5 卡时建议不适用于本轮七组方案。

A/B 应在本轮相同环境和新运行入口下重新运行，旧 A/B 的 6/10 仅作历史参照。接入与协议检查完成后，第一轮的早期任务用于确认真实运行与耗时，不再单独用盘子、锅铲两题筛选提示词。发生协议错误或预计越过预算上限时保留日志并报告；不要把技术中断冒充任务失败，或悄悄删除未完成任务。
